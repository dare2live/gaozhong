# 交付运营就绪度评估 (2026-06-20)

> 总控级评估: 离 goal.md "可对内部教研团队交付试运营" 还差什么 (操作/运营层, 非细节)。
> 方法: 7 层并行评估(8-agent workflow) + 控制器综合。配 goal.md 第四阶段复核门 + Rule10。
> **一句话裁决**: 距交付约差**一个收口冲刺(operational sprint), 不是一个建设阶段**。

## 0. 整体裁决

数据/分析底座 + KG 分析层 + 工程门禁 **已实质就绪**(高中侧真值扎实经对抗验证, 三门 live 全绿, PIT 血缘成立)。交付 bar 4 项里 **2 项硬缺口卡死**:

| 交付 bar (第四阶段复核门) | 状态 |
|---|---|
| 数据 100% 准 (D0 铁律) | ✅ 达成 (D0 36项 + moth 70 + stop_gate, live 全绿) |
| 前端 3 端统一可用 | ⚠️ 碎片化 (新 8-tab app 壳 + 旧 /teacher 两套 UI; 金矿未接前端) |
| Docker 服务器实跑 | ❌ **完全缺失** (无 Dockerfile, 单机 localhost) |
| **1 名辽宁老师真用 30 分钟反馈入档** | ❌ **从未发生** (所有"就绪"是工程自证, 缺唯一独立真相源) |

**关键判断**: 别让"还能建更多 KG 维度/更多关联"无限延迟那个**比建设更高杠杆的真老师校验**。若把试运营收窄为 **"单台教研机 · 1-2 名可信老师 · 高中真题分析+备课视图最小集"**, 则只差一周内可补的工程收口 + 用户动员真老师; 若坚持 "多人服务器 + 成品讲义 + 真学情", 则差一个阶段。**建议走前者。**

## 2. 到试运营的关键路径 (有序)

1. **[用户拍板·起点]** 试运营**形态**(单机1台教研机 vs 服务器多人)+ **范围**(高中真题分析+备课视图最小集 vs 含中考/讲义/真学情)。这一拍板决定下面哪些是阻塞、哪些可延后。
2. **[AI]** 统一前端入口: `/` 默认指向新 app 壳, 把旧 /teacher 的单元备课(lesson)+组卷(compose)迁进 8-tab, 消除老师跨两套 UI 跳转(纯前端, 后端 API 已就绪)。
3. **[AI]** **把已建金矿开矿口**: `exam_vocabulary` 考试词典 + `word_sense` 跨阶段多义接进 teacher 前端页面 + nav(API 已存在, 纯前端小工作量)。否则 KG 最值钱两维老师根本点不到。
4. **[AI]** 学情面板给明确空态引导("先导入班级名单/上传答题卡"), 把裸"无数据"变可操作引导; 不在零真实作答上假装满看板。
5. **[AI]** 最小部署达标: Dockerfile + compose(单容器 python3+DuckDB 卷挂载, server 绑 0.0.0.0)+ 最小服务端鉴权(只改 `_tenant.get_teacher` 单点 + 一个登录端点, 不动 7 业务端点)。
6. **[最高杠杆·用户动员]** **1 名辽宁英语老师真用 30 分钟**走"查考点→备课→组卷→看学情"一条线, 反馈卡点入档。**这一步不过, 交付 bar 不算达成**, 且它的反馈直接决定第 7 步建什么。
7. **[按反馈]** 再决定: 讲义重建? 语法考点维? 续写/应用文? —— 而非现在凭 AI 自评预建。

## 3. 最高杠杆 (Rule10, AI 做不了)

**动员 1 名辽宁一线英语老师真用 30 分钟并把反馈入档。** 这是交付 bar 的硬项, 也是唯一能把六层"工程自证的就绪"变成"事实就绪"的独立真相源(goal.md 反复强调, 第四阶段复核门明列)。它同时是最高杠杆的**范围裁决器**——真老师会一句话告诉你"备课骨架够不够 / 要不要成品讲义 / 学情面板可不可读", 从而砍掉一大批 AI 凭空预建的工作。**比继续建任何 KG 维度都高杠杆。** 务必先做到能让老师真跑通一条线(第 2-5 步收口)再请老师, 否则浪费这次稀缺校验。

## 4. 分工

### AI 现在能补 (排序; 都是收口非建设)
1. 统一前端入口(迁 lesson+compose 进 app 壳)。
2. 考试词典 + word_sense 接前端(开矿口)。
3. Dockerfile + compose(部署 bar 直接前提)。
4. 最小服务端鉴权(只改 `_tenant.get_teacher` 单点 + 登录端点)。
5. 学情 tab 空态引导 + 可演示种子。
6. 逐年加卷 ops_runbook SOP + `import_recent_exams` 硬编码路径改 `source_versions` 驱动(架构门已标 BLOCK 债)。
7. 教学方案层升"教案骨架"(加目标/导入/讲练环节)+ 缝作业(复用 compose)+ 打印/导出 —— 但深浅待真老师校准。

### 需用户拍板
- 试运营**形态** + **范围**(路径起点, 决定阻塞集)。
- 讲义重建定位: "备课骨架"(骨架+真题基本够, 重建非阻塞) vs "40节成品课"(必须先重建)。
- **动员真老师**(Rule10 硬项)。
- 鉴权身份源(教研团队账号 / 对接学校登录)。
- 语法考点/句型/表达/命题方式 是否纳入试运营(真相源未成熟, 坑16 风险, 战略决策)。

### 试运营可不阻塞·别过度建 (奥卡姆 + operating rule6)
- 中考侧考题(walled)—— 当前 trial bar 高中导向, 整体延后, 别为它搞版权/渠道。
- 逐年趋势 slope —— 辽宁数据客观稀缺, era 分段分布快照即可, 已诚实降级。
- KG 立体透视 stereo_query + 语法考点/句型/表达三维 —— design 承诺但真相源未成熟, 现有几张分布图够; 真老师校验前别预建。
- 命题方式 exam_method 第二轴 —— 先 docs 沉淀。
- 续写/应用文写作层 —— 写作老师若是首批试用者再补, 别提前合成范文(违 §1.1 + C 层须教师校验)。
- 完整 IAM / 多人异地部署 —— 单机/小范围可信内网先跑。
- 讲义/范文/趣味化生成层重建 —— 总目标产物但应先经真老师验证"骨架够不够"再决定(§1.1 阻塞已解除 ≠ 现在必须建)。
