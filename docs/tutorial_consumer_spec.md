# 教程载体定义 spec（复核门）

> 立法层产物（架构师 controller）。2026-06-15 用户认领定义权后落档。
> 作用：这是"为谁、做成什么、怎么算验收"的**单一真相**，所有下游分析/可视化/数据维度都要能反证服务于本 spec。
> 状态：**草案 + 未经真实老师验证**（critic 盲点 #1：消费者从未被验证）。真老师 30 分钟试用前，本 spec 是假设不是结论。

## 0. 一句话

**面向教师、兼顾学生的一体化工具：老师用它「备课 + 讲课 + 分析学生」，数据脊柱是「每个学生的档案 / 错题库」。**

## 1. 对象（who）

| 主对象 | 次对象 |
|---|---|
| 辽宁高中英语**教师**（备课、讲课、分析学生） | **学生**（通过错题库/档案被分析，间接受益） |

不是"学生自学题集"，不是"通用刷题 App"。一切围绕**老师的教学工作流**。

## 2. 形态（what）— 三位一体

| 功能 | 形态 | 依赖的数据维度 |
|---|---|---|
| **备课** | 考点地图 + 命题趋势 + 考点分布（"考什么、近年怎么考、教到哪一步该练什么"）| 真考点维度（件2）+ province-scoped 趋势（件1）+ 真题↔课标↔教材关联 |
| **讲课** | 课堂浮窗：实时「真题 ↔ 考点 ↔ 课标条目 ↔ 教材出处」一键追溯 | 4 路关联闭环（图谱 edges）|
| **分析学生** | **学生档案 / 错题库** → 薄弱环节分析 | 错题 ↔ **真考点** 映射（决定薄弱环节是否成立）|

**数据脊柱 = 学生档案 / 错题库**：每个学生的错题入库 → 每道错题映射到真考点 → 聚合出该生薄弱环节 → 反哺老师备课。

## 3. 验收（how，复核门）

下游任何"分析/可视化/教程素材"产物，验收必须同时满足：

1. **服务老师工作流**：能答"这个产物老师在备课/讲课/分析学生的哪一步用、怎么用"。答不出 = 为分析而分析（感知死信号）。
2. **错题→薄弱环节链路成立**：student_weakness 的每条必由 student_answers + **真考点**标注支撑（非 word-token；现状 25 行建在 token 冒充考点上，待件2 修）。
3. **分析诚实（D0 扩展）**：趋势/分布带样本量 n，n<阈值标 `样本不足`；考点标注带 provenance（human/dual_model/llm）；不偏离学校（词量≤课标3500+已学单元）。
4. **真人验证门（最高，未达）**：1 名辽宁高中英语老师真用 ≥30 分钟 + 3–5 条反馈，确认"考点地图/趋势图/错题分析"真用得上、不误导教学。**这是 controller Rule 10「people are not agents」——只能由用户去动员真老师，AI 做不了。**

## 4. 与既有约束的对账

- §1.1 数据基石优先：真题/考点/关联地基未夯实前**不建教程库**（用户 2026-06-15 重申"不着急建教程库"）。
- §1.2 不偏离学校：选题可借鉴雅思真源（TIME/科学美国人/TED）的**话题方向**，但文本必须改写降级到课标词表（详 [exam_topic_landscape.md](exam_topic_landscape.md) 选题方法论）。
- 核心竞争力（[[feedback-core-competency]]）：考点趋势+热力图+关联 = 本 spec 的"备课"与"分析学生"两支柱的技术地基。

## 5. 死亡条款（本 spec 何时作废）

- 真老师试用后明确"用不上 / 会误导" → 本 spec 重写，对象/形态回炉。
- 3 个月内无任何老师真实使用 → 感知死，停止在其上叠加分析。
